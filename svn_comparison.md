## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
В Git ветка — это всего лишь указатель (ссылка) на коммит, размером ~41 байт.
Создание ветки — мгновенная операция, не требующая копирования файлов.
В SVN ветка — это физическая копия директории в репозитории (через `svn copy`),
поэтому она занимает место и выполняется заметно дольше.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет. SVN — централизованная VCS: история и рабочая копия хранятся на сервере.
Локально можно менять файлы, но зафиксировать изменения (commit) нельзя —
нужен доступ к серверу. В Git коммит делается локально, потому что у каждого
разработчика есть полная копия репозитория с историей.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
- Legacy-проекты банков и госсектора, где уже выстроены процессы вокруг SVN.
- Команды с жёстким централизованным контролем доступа к отдельным каталогам
  (в SVN это делается через path-based авторизацию «из коробки»).
- Хранение больших бинарных файлов (ассеты, модели), где Git без Git LFS неудобен.
- Простые линейные проекты, где распределённая модель Git избыточна.
